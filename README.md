# 英単語・熟語学習アプリ

高校入試対策用に、英単語1,652語・熟語396個を**復習スケジュール**と**音読**で覚えるための
家族用アプリ。仕様は [SPEC.md](SPEC.md)、初期データは `vocab_seed.json`。

## 形態: PWA(iPhone / Android 共通)

SPEC §2 の推奨は Expo(React Native)だが、**PWA(§2 の代替案)で実装した**。

- 開発機に node / npm が入っておらず、Expo のビルド環境を作れない
- PWA なら1つのURLで **Android と iPhone の両方**で動き、ホーム画面に追加すれば
  アプリのように全画面で使える。ストア登録も証明書も不要
- iOS 配布に必要な Apple Developer Program(年額約99ドル)と、約90日ごとの再ビルドが不要
- 既存の [checklist-app](../checklist-app) / [pomodoro-app](../pomodoro-app) と同じ構成

## 使い方

1. ブラウザで公開URLを開く
2. **ホーム画面に追加**する
   - Android(Chrome): メニュー → 「ホーム画面に追加」/「アプリをインストール」
   - iPhone(Safari): 共有ボタン → 「ホーム画面に追加」(**Safari で開く必要がある**)
3. 設定(右上の ⚙)で**入試日**を入れる
4. **Wi-Fi につないでから**、ホームの「ダウンロード」で音声データ(約8.7MB)を入れる
5. あとはホームの「今日のタスク」を上から消していく

家族で使うときは、ホーム上部のバーから**プロフィールを追加**する(最大5人)。
進捗・設定・追加した語はプロフィールごとに分かれる。

データは端末のブラウザ内(localStorage)だけに保存する。サーバーには何も送らない。
機種変更のときは設定画面の「進捗を書き出す / 読み込む」を使う(プロフィール単位)。

## 画面

| タブ | 内容 |
|---|---|
| ホーム | プロフィール切り替え、学習計画、優先度Aの進み具合、今日のタスク、音声のダウンロード |
| 単語 | 一覧・検索・絞り込み(優先度/学習日/ステージ)・語の追加。ここから学習を開始 |
| 熟語 | 同上(熟語) |
| 音読 | セット選択 → ①聞く ②リピート ③シャドーイング ④暗唱 |
| 統計 | 日別の学習語数、優先度別の定着率、弱点リスト |
| 設定(⚙) | 新規語数、入試日、音声、音声データ、通知時刻、バックアップ、初期化 |

## 復習スケジュール

ステージ0〜5の固定間隔(SPEC §4.3)。

| ステージ | 次回まで |
|---|---|
| 0(新規) | 当日 |
| 1 | 1日後 |
| 2 | 3日後 |
| 3 | 7日後 |
| 4 | 30日後 |
| 5 | 卒業(もう出ない) |

- `✓ 覚えた` … ステージを1つ上げ、次回日を `今日 + 間隔[新ステージ]` にする
- `△ あやふや` … ステージ1に戻し、翌日もう一度出す
- 期限切れはその日に最優先。ただし1日の復習は60語まで(超えた分は翌日)
- 定着率 = ステージ5の語数 ÷ 全語数

## 音読の音声

熟語の例文396文は、**事前に生成した音声を同梱**している(`audio/`、約8.7MB・792ファイル)。
速度は **1.0倍 → `normal` / 0.8倍 → `slow`** とファイルを切り替える(`playbackRate` は使わない)。
音声が無い文(ユーザーが追加した例文)は、端末の読み上げ(Web Speech API)で代用する。

**ダウンロードは自動で始まらない。** モバイル回線の通信量を使わせないため、
開始は必ずユーザーの操作にしてある(§4.5.1)。

- **まとめてダウンロード**: ホームか設定のボタンから。20件ずつ取得し、途中で閉じても続きから再開する
- **セット単位**: 音読セットを開くと、そのセットの20ファイル(約0.2MB)だけ取得する

## ファイル構成

```
index.html                 画面の器(タブとヘッダーだけ)
css/style.css              見た目。ダークモード対応・rem指定で文字サイズ拡大に追従
js/
  app.js                   画面の切り替えと起動
  srs.js                   復習ロジックと学習計画(副作用なしの純粋関数だけ)
  store.js                 localStorage の読み書き、プロフィール、シードの取り込み
  audio.js                 例文の再生(同梱mp3 → 無ければ読み上げ)
  audiocache.js            音声のダウンロードとキャッシュ
  tts.js                   読み上げ(Web Speech API)のラッパーと速度の定義
  notify.js                リマインド通知
  ui.js                    エスケープ・モーダル・トーストなどの小道具
  screens/                 画面ごとの描画
audio/                     同梱音声(manifest.json + normal/ + slow/)
vocab_seed.json            初期データ(単語1,652・熟語396)
sw.js                      Service Worker(オフライン動作)
test.html, test/           テスト
```

## 設計のメモ

- **シードは毎回 JSON から読み、進捗だけを保存する**。進捗は語ID(`w0001` など)で
  持つので、`vocab_seed.json` の `version` を上げて語を足しても進捗は消えない(SPEC §6)
- **新規語の枠は単語と熟語で別々に数える**。進捗オブジェクトは共通なので、
  絞らずに数えると単語を学習した分だけ熟語の新規枠が減る(実際に踏んだバグ)
- **音声は本体とは別のキャッシュ**(`eitango-audio-v1`)に入れる。コードを更新して
  本体のキャッシュ名が変わっても、8.7MB を再ダウンロードさせないため
- **`Audio` 要素は1個を使い回す**。1つの要素は1つの音源しか再生できないので、
  「次へ」で音が重なることが構造的に起こらない。iOS の自動再生制限にも都合がよい
- **リピートの無音は、音声ファイルの実測 `duration` + 1秒**。文字数からの推定ではない
- **回線の種類は判定しない**。iOS Safari は Network Information API 非対応で、
  Wi-Fi かモバイルかを確実に知る方法が無い。できない判定を、できるように見せない
- **`sw.js` はページ・スクリプト・単語データをネットワーク優先**にし、
  `fetch(req, { cache: "no-cache" })` で必ず検証させる。
  キャッシュ優先だと、配信側を更新しても端末に古い版が残り続ける
- **先読みリストの漏れをテストで止める**。`index.html` から `import` をたどって
  必要なJSを割り出し、`sw.js` の `ASSETS` と突き合わせる。
  1ファイルの漏れでオフライン起動が壊れる(実際に踏んだ)

## 制限

- **閉じている間の通知は出せない**(PWA の制限)。アプリを開いているときに、
  設定時刻を過ぎていて今日の分が残っていれば通知する
- **画面を閉じている間の読み上げには対応していない**。画面を表示したまま練習する
- **iOS は最初の再生がタップ起点である必要がある**(iOS 側の仕様)
- **iOS はキャッシュを消すことがある**。長期間使わないと音声が消えるが、
  次に開いたとき取り直せる
- シードデータはAIが選んだ語彙で、教科書の掲載順とは一致しない(SPEC §10)
